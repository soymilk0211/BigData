# 課程講義：student-rental-check——台灣學生租屋行情與避雷 Claude Skill

> 本講義搭配影片（`student-rental-check_final.mp4`，總長 4:45，Google TTS 旁白＋燒錄字幕）與字幕 `subtitles.zh-TW.srt` 使用。括號中的時間是影片時間點，章節表見 `chapters.md`。所有數字都來自 `test-logs/` 的實際執行紀錄。

## 1. 這個 Skill 做什麼（0:00–0:40）

- **名稱**：student-rental-check（台灣學生租屋行情與避雷檢查）。
- **要解決的問題**（0:09–0:17）：學生找房常遇到三件事——不知道租金合不合理、看不到管理費與水電等隱藏成本、訂金詐騙。
- **資料來源**（0:17–0:30）：
  - 內政部**實價登錄**「不動產租賃」開放資料：每季一個壓縮檔，全國 21 個縣市各一個檔案。
  - 實價登錄的**備註欄**常寫管理費，collector 會解析出來。
  - **591 租屋網**的刊登資料只當補充對照：刊登價≠成交價，兩者並列、永不合併。
- **預期成果**（0:30–0:40）：一份 `final_report.md`，九個章節，包含行情位置、**真實每月總成本**（已知項目合計＋未提供項目）、踩雷提醒、審查紀錄與看房殺價話術。

## 2. Skill 架構（0:40–1:24）

- 資料夾依老師範本命名為 `team-XX-skill/`，內含 `SKILL.md`、`agents/`、`scripts/`、`references/`、`sample-data/`（畫面 0:09–0:40）。
- **Trigger（觸發條件）**＝ `SKILL.md` 開頭 frontmatter 的 `name` 與 `description`（0:40–0:55）：
  - 應啟動：學校附近找房、租金合不合理、真實每月成本、擔心訂金或踩雷。
  - 不要用於：買房／預售屋、國外租屋、一般程式問題、房東定價等。
- 角色之間用 **handoff 交接檔**（`handoff_<n>_<角色>.json`）傳遞資料（1:19–1:24）。

### 五個 Agent（0:55–1:19）

| # | Agent | 只負責 | 何時啟用 |
| --- | --- | --- | --- |
| ① | **collector** 蒐集員 | 解析地區（縣市＋區、學校查表、地址），取得實價登錄與 591 資料，整理候選物件 | 一律 |
| ② | **fact-checker** 時效驗證員 | 標記過時、重複、來源不明、未提供的資料；**只標記、不刪資料** | 一律 |
| ③ | **quant-analyst** CP 值精算師 | 行情統計（中位數、四分位數）、真實每月總成本、排序、刊登租金對照、判定高風險訊號 R1–R7 | 一律 |
| ④ | **devil-advocate** 踩雷獵人 | 挑戰排名第一的物件，寫踩雷報告 | **條件啟動**：只有 R1–R7 有訊號時 |
| ⑤ | **reviewer** 審查員 | 用獨立腳本 `recompute.py` 從原始資料重算抽查 V1–V13，組成最終報告 | 一律 |

流程：使用者需求 → Trigger → collector → fact-checker → quant-analyst →（有訊號才）devil-advocate → reviewer → `final_report.md`。

**devil-advocate 什麼時候啟動？** quant-analyst 寫出 `03_signals.json`；`signals` 非空（例如 R3「先匯訂金才能看房」）就啟用 devil-advocate；`signals` 為空就略過，並在 `00_routing.json` 的 `agents_skipped` 記錄 `no_high_risk_signal`，而且**不讀** `agents/devil-advocate.md`（測試 A 就是這樣，2:18–2:24、2:37–2:41；測試 B 則有啟動，3:20–3:33）。

## 3. 怎麼證明 Skill 有自動啟動：證據等級 E0–E3（1:24–2:04、2:31–2:51）

測試都用 Claude Code 非互動模式 `claude -p … --output-format stream-json --verbose` 執行，提示詞**沒有指名 Skill、沒有斜線指令**（自動觸發）。不是只看回答，而是用 `jq` 檢查 stream-json log（測試 A 段最後，約 1:51–2:04）：

| 等級 | 證據 | 意義 |
| --- | --- | --- |
| E0 可用 | `system/init` 事件的 `skills` 含 `student-rental-check` | 只證明已安裝，不算啟動；反向測試用它證明「沒啟動不是因為沒裝」 |
| E1 自動選用 | `tool_use.name == "Skill"`、`input.skill == "student-rental-check"` | **主要證據**（影片中即時執行的第一個工具呼叫，1:33–1:42） |
| E2 依分工執行 | 之後用 Read 讀 `agents/*.md`、用 Bash 執行 `scripts/*.py` | 照 SKILL.md 的角色與路由執行 |
| E3 可核對輸出 | `output/<run_id>/` 檔案、`validate.py` 結束碼 0、`05_review_log.json.verdict` | 產出符合規格 |

## 4. 測試結果

### 測試 A：應啟動（1:24–2:51）

- 提示詞：長庚大學新生，龜山區獨立套房，月租 9,500 元、權狀 8 坪、管理費 800 元、電費每度 5 元、騎車單程 12 分鐘。
- **即時執行**（1:24–2:04）：影片中用 `claude -p` 即時跑測試 A（`test-logs/LIVE-A.jsonl`），第一個工具呼叫就是 Skill（E1），接著用 Read 讀 `agents/collector.md`（1:42–1:47）。為了省用量只跑 9 個回合（`--max-turns 9`，結束於 `error_max_turns`，是刻意設定），畫面加速 1.5 倍。
- **各角色腳本直接執行**（2:04–2:31）：在 `sample-data` 上離線執行 resolve_area → collect_lvr → candidates → flag → analyze → recompute：collector 解析出桃園市龜山區、約 4,500 筆；fact-checker 標記三千七百多筆、刪除 0；沒有高風險訊號，devil-advocate 不啟動；reviewer 資料階段 23 項檢查全部 PASS。
- **完整執行紀錄**（2:31–2:51，`test-logs/V-A.jsonl`）：Skill 自動呼叫（E1）→ 依序讀 collector、fact-checker、quant-analyst、reviewer 四個角色檔（2:31–2:37）→ 沒有高風險訊號，`00_routing.json` 記錄略過 devil-advocate，**沒有讀 devil-advocate**（2:37–2:41）。
- 數字：分析地區桃園市龜山區（使用者指定）；每坪 1,187.5 元，套房行情中位數 1,188.5 元；**真實每月總成本：已知項目合計 12,618 元**（= 月租 9,500＋管理費 800＋電費 750＋通勤時間成本 1,568），未提供：水費、瓦斯、網路（2:41–2:51）。
- 穩定性：正式測試 A-1–A-4 共 4/4 自動啟動。
- **V-A 這次完整執行的審查結果是 FAIL**（4:00–4:11）：reviewer 的 V8（報告數字可追溯）把報告抄錄的審查對帳筆數 4446、3588 判為無法追溯。數字本身沒錯，是規則自相矛盾，已修正（見第 5 節）。

### 測試 B：換說法、換城市，仍應啟動（2:51–3:33）

- 提示詞：在**逢甲**附近找房，兩間比較：第一間分租套房 7 坪、月租 7,000，房東要**先匯訂金才能看房**；第二間雅房 5,500，管理費不知道。
- **即時執行**（3:00–3:08，`test-logs/LIVE-B.jsonl`，只跑 7 個回合，結束於 `error_max_turns`）：第一個工具呼叫就是 Skill，接著 Read `agents/collector.md`。
- collector 用學校對照表把「逢甲」對應到**臺中市西屯區**（`school_lookup`，3:00–3:08）。
- 完整紀錄（`test-logs/V-B.jsonl`）：Skill 自動啟動，**五個角色都出現**（3:24–3:29）。
- 第一間命中 **R3：先匯訂金** → 路由啟用 devil-advocate；踩雷獵人把第一間判為 high（高風險），建議避開（3:20–3:33）。排名：第二間（5,500）第 1、第一間（7,000）第 2；但「排名第一不等於可以租」。
- reviewer 審查 PASS（30 項檢核）。
- **不限長庚**：測試 B 在台中，證明 Skill 不限長庚附近，全台各縣市都能用（3:00–3:08）。
- V-B 那次的最終文字回覆被帳號的 5 小時用量上限截斷，但流程已經跑完且審查 PASS，不是 Skill 失敗。

### 測試 C：不應啟動（3:33–3:44）

- 影片中**即時執行**（`test-logs/LIVE-C.jsonl`，完整跑完）：問一個一般的 Python 問題，模型 1 個回合直接寫出程式碼（3:33–3:38）。正式反向測試 C-1–C-3 的提示詞是「幫我寫一個 Python 函式，輸入兩個日期字串，回傳相差幾天。」
- 證據：init 顯示 Skill 已安裝（E0），但 Skill 呼叫次數是 0 → 沒啟動是模型依 description 判斷的結果（3:38–3:44）。
- 近似題也全部沒有誤觸發（影片未逐題展示，見 `test-report.md`）：林口預售屋（買房）、長庚圖書館開放時間（校務）、東京學生套房（國外）、租屋押金法規上限、房東想出租定價、寫 591 爬蟲（程式）。C 3/3、近似與邊界題 6/6 都未啟動。

## 5. 除錯紀錄（3:44–4:18）

- 開發試跑遇到 **7 個實際問題**（影片舉 cat 這一例，3:52–4:00），例如：
  - 模型用 `cat` 讀角色檔，log 看不到 Read 紀錄 → SKILL.md 明確要求「用 Read 工具讀 agents/<角色>.md」，之後 E2 證據完整。
  - reviewer 的 V10 抓到實價登錄備註裡的姓名和電話（官方原始資料）→ 加上遮蔽規則。
- **description 第一次就通過**，沒有為了製造失敗而改壞它；SKILL.md 本體改成範本的九個章節（v1 → v2），重跑 A、B 仍然通過（3:44–3:52）。
- **回歸測試 A-4 審查 FAIL → 修正 → PASS**（影片未展示，見 `test-report.md` 4.4 節）：報告寫了管理費解析筆數，但這些數字不在任何檔案中 → 新增 `03_mgmt_fee_status.csv`，並規定「讓數字可追溯，不是刪掉數字」（RT16）。
- **V-A 完整執行的 V8 FAIL（影片 4:00–4:11）→ 修正 → 重跑 A-5 PASS、validate 通過（4:11–4:18）**：第 8 節引用 V3 對帳筆數（4446/4446）與 V7 納入＋排除（3588+912），這些是本次 reviewer 自己重算的值，但 V8 不把 `05_review_log.json` 當來源；改報告後又照抄第一次問題原文，數字再被判一次。修正：V8 把本次資料階段檢核（V1–V7、V12、V13）的重算值當作可追溯來源；第 8 節改抄不含原始數字的摘要 `report_first_issues_summary`。修正後的回歸測試結果見 `test-report.md`（測試 A-5）。
- reviewer 會從原始資料**獨立重算**（1:15–1:19、2:24–2:31）：V1 各季筆數、V2 抽樣 5 筆換算坪數與日期、V3 四千多筆每坪單價全部對帳、V4 分組統計、V5 真實總成本重算一致、V7 不刪資料、V8 報告數字可追溯、V10 不含個資。

## 6. 限制（4:18–4:29）

- 實價登錄只含**有申報**的案件；**社會住宅**比例高的地區會拉低行情（龜山約 2362/3700 筆）；坪數是登記面積、**含公設**。
- 591 是刊登價、坪數是使用坪數，不能和實價登錄每坪租金直接比較。
- 學校對照表只收錄少數學校，其他學校請直接給「縣市＋區」。
- 物件事實沒寫就標「未提供」，不補預設值，所以真實每月總成本只代表已知項目。
- 時間價值（基本工資時薪）與電費每度上限未能取得官方原文，標「未驗證」；R5 暫停判定。
- 測試都是非互動模式；互動模式的「追問一次」沒有在 log 中驗證。

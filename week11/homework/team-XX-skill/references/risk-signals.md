# 高風險訊號 R1–R7（devil-advocate 與 analyze.py 共用）

任一訊號成立，就啟用 devil-advocate。訊號由 `scripts/analyze.py` 判定並寫入 `03_signals.json`；判定不了的寫在 `not_evaluated`，報告要照列。

| 訊號 | 判定 | 門檻 | 不判定的情況 |
| --- | --- | --- | --- |
| R1 價格過低 | 候選每坪租金 < 同組 `lower_fence`，或 < 同組 P10 | `iqr_k = 1.5` | 沒有坪數；坪數是 591 使用坪數（與實價登錄登記坪數基準不同）；行情分組 `insufficient` |
| R2 價格過高 | 候選每坪租金 > 同組 `upper_fence` | 同上 | 同上 |
| R3 可疑話術／條件 | 使用者描述或 591 刊登內容命中下方關鍵字 | 關鍵字表 | — |
| R4 押金過高 | 押金月數 > `deposit_cap_months`（2） | 租賃住宅市場發展及管理條例第 7 條 | 押金未提供 |
| R5 電費每度過高 | 每度電價 > `elec_cap_per_kwh` | 上限未驗證 | 上限為 null 時一律不判定，報告寫明 |
| R6 來源可疑 | 同時有 `UNKNOWN_SOURCE` 與 `STALE_LISTING`，或 warn 以上旗標 ≥ 2 | — | — |
| R7 評論負面集中 | 同一地區使用者提供的評論中，負面關鍵字（漏水、壁癌、隔音差、蟑螂、押金不退、房東擅自進入）命中 ≥ 2 則 | `neg_review_min = 2` | 沒有評論（本 Skill 不使用模擬評論） |

「管理費未提供」「無電梯」等是一般提醒，不單獨觸發 devil-advocate。

「轉租」只有在未提及房東同意書時才算；腳本不判斷這一點，由 devil-advocate 讀原文確認。

## 風險等級與建議

- 只有 R1、R2、R5 → `medium`；含 R3、R4 或 R6 → `high`；只有 R7 → `medium`。
- `recommendation` 只能是：`可接受但需確認`、`看房前必問`、`建議避開`，可加一句說明。

## 每個訊號的可能情況與必問問題

| 訊號 | 可能情況 | 看房或簽約前必問 |
| --- | --- | --- |
| R1 | 屋況差、違建或頂加、隔間套房、詐騙誘餌、社宅包租價 | 有沒有使用執照與產權登記？是否頂加或隔間？可以先看房嗎？ |
| R2 | 含家具家電或管理費、新裝潢、刊登價偏高 | 租金含哪些費用？可否議價？同棟其他房間價格？ |
| R3 | 未看房先收款是常見詐騙；不能報稅入籍常見於規避稅負或違規出租 | 可否先看房再付訂金？是否開收據？可否報稅、入籍、申請租金補貼？ |
| R4 | 超過法定押金上限 | 押金為何超過兩個月？是否願意依法調整？ |
| R5 | 電費加價 | 有沒有獨立電錶？每度怎麼算？夏季與非夏季是否不同？ |
| R6 | 刊登過期或資訊不完整 | 物件是否仍可租？刊登者身分（屋主、代理人、仲介、二房東）？ |
| R7 | 同區屋況問題集中 | 有無漏水壁癌紀錄？隔音如何？押金退還條件？ |

法規只寫「請向主管機關或官方資料確認」並附條文名稱，不下法律結論。

# AGENTS.md

## Project
Data analysis and visualization in Python. Turn a dataset into correct, readable charts and explain what they show.

## General rules
- Use the project's existing Python environment (venv). Run `python --version` and report it. Do not assume a fixed version.
- Use only pandas, matplotlib, seaborn and plotly. Do not install other packages without asking.
- If a request conflicts with this file, stop. Name the rule, propose a compliant alternative, and ask. Do not skip the rule silently and do not edit this file.

## 1. Data inspection (before any plot)
Inspect the data first and print a short summary:
- Columns: names and meaning. Ask if a column is unclear.
- Data types: convert dates, booleans and numbers stored as text.
- Missing values: count per column.
- Duplicates: count fully duplicated rows and repeated IDs.
- Implausible values: negative sizes or times, percentages outside 0-100, dates out of range, extreme outliers (outside 1.5 x IQR). Report them; do not remove them silently.
- Cleaning or transformation: decide whether it is needed, say what was done, and say how many rows were affected. Never fill in missing values without saying so.

## 2. Tool selection
State the chosen package and the reason in one sentence. If the user names a package, use it.
- Matplotlib (default): fine control of layout, labels and annotations; static figures for reports.
- Seaborn: distributions, group comparisons, correlations (box, violin, histogram, heatmap, pair plot).
- Plotly: interactive exploration (hover, zoom, filter); time series; more than about 2,000 points; output as HTML.
- Use one package per figure. Do not mix packages in a single figure.

## 3. Chart rules
Required for every chart:
- Title that states what is shown.
- X and Y axis labels, with units.
- Legend when there is more than one series or color.
- Colors: at most 8 categories; the same category keeps the same color in all figures.
- Size and text: figsize (8, 5) or larger, font size 10 or larger, saved at 150 dpi or more, no overlapping labels.
- Chart type matches the question: trend -> line, category comparison -> bar, distribution -> histogram or box, relationship -> scatter, correlation -> heatmap.

Use when applicable:
- Annotation: mark only key points (maximum, minimum, turning point, threshold) that support the finding.
- Too much data (more than about 5,000 points or heavy overplotting): use transparency, sampling, binning or aggregation, and say which.
- Log scale: when values span 2 or more orders of magnitude. Label the axis as log scale. Never use it with zero or negative values.
- Interactive chart: only when the user needs to explore or hover. Otherwise save a static PNG. Interactive charts must still meet all required rules above.
- Bar charts start at 0.

## 4. Output rules
- Python code: `src/`.
- Static figures: `outputs/figures/` as PNG.
- Plotly HTML: `outputs/html/`.
- Cleaned data: `data/processed/`.
- File names: lowercase snake_case, no spaces, in the form `<dataset>_<chart>_<variables>.<ext>`, for example `sales_line_revenue_by_month.png`.
- Raw data in `data/raw/` is read-only: never modify, delete or overwrite it. Always keep it. Write cleaned results to a new file in `data/processed/`.
- Overwriting: files the agent generated in `outputs/` and `data/processed/` may be regenerated by rerunning the script. Never overwrite any other file; ask first or add a `_v2` suffix.

## 5. Final self-check
Before finishing, run the script and confirm:
1. The correct columns were used, with the right units.
2. The script runs without errors (report the command and result).
3. The chart is easy to read: title, labels, legend, no overlap.
4. The chart type suits the question and the data.
5. The output files exist at the expected paths (list them).
6. Explain in 2-3 sentences what the chart shows, with numbers, and mention any cleaning or data limits.
Report every deviation from this file.

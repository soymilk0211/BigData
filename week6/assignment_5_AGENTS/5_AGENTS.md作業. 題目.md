## 題目說明

上一堂課中，我們透過撰寫 Prompt，練習如何明確告訴 AI：
- 使用哪一種資料視覺化套件
- 使用哪一種圖表
- X / Y 軸使用哪些欄位
- 如何進行分組
- 想要凸顯哪些資訊
- 是否需要互動、標註或輸出檔案

本次小專題請將這些「每次都可能需要告訴 AI 的要求」，進一步整理成一份可重複使用的 **`AGENTS.md`**。

目標：

建立一份「資料視覺化專案規範」，讓 Coding Agent 在處理不同資料與不同視覺化需求時，都能依照小組制定的原則，自動完成資料檢查、工具選擇、圖表製作與成果輸出。
設計一套能夠套用到不同資料視覺化工作的通用規則

# 任務要求

## 1. 製作一份 Data Visualization `AGENTS.md`

請小組共同討論並完成一份適合「資料分析與資料視覺化專案」使用的 `AGENTS.md`。

內容至少必須涵蓋以下面向。

### 資料檢查

規定 Coding Agent 在開始畫圖以前，應該如何了解資料，例如：

- 資料欄位
- Data type
- Missing value
- 重複資料
- 異常或不合理數值
- 是否需要進行資料清理或轉換

---

### 視覺化工具選擇

請制定規則，讓 Agent 能根據不同需求，在下列工具中選擇適合的套件：

- Matplotlib
- Seaborn
- Plotly

上一堂課已經分別使用三套工具進行不同類型的視覺化，例如 Matplotlib 著重圖表控制與標註、Seaborn 著重統計分布與相關性分析、Plotly 著重互動式資料探索。  

請將你們認為適合的「選擇條件」寫進 `AGENTS.md`。

---

### 圖表規範

請制定你們認為一張合格的資料視覺化應該遵守哪些規則，例如：

- Title
- X / Y axis label
- Legend
- 顏色與分組
- Annotation
- 圖表大小
- 資料過多時的處理方式
- Log scale 的使用時機
- Interactive chart 的使用時機

討論哪些規則應該成為「所有視覺化工作都必須遵守的共同要求」。

---

### 輸出規範

請規定 Coding Agent 完成工作後：

- Python 程式應放在哪裡
- 圖片應放在哪裡
- Plotly HTML 應放在哪裡
- 檔案如何命名
- 是否需要保留原始資料
- 是否可以直接覆蓋既有檔案

---

### 成果檢查

請要求 Agent 在任務完成前進行自我檢查。

- 是否使用正確欄位
- 圖表是否能正常執行
- 圖表內容是否容易閱讀
- 是否使用適合的視覺化方法
- 是否成功輸出檔案
- 是否能簡單說明圖表中觀察到的結果
